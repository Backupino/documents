# ۱. عیب‌یابی و حل خطاهای پایگاه داده و SQL

> **بخش:** عیب‌یابی • **نسخه پایدار:** ۱.۰.۰ رسمی • **آخرین به‌روزرسانی:** نوامبر ۲۰۲۶  
> **مخاطب:** توسعه‌دهندگان، مدیران هاست و دیباگرها

---

## 🛠️ ۱. خطای `Got a packet bigger than 'max_allowed_packet' bytes`

### نشانه:
در حین ایمپورت دیتابیس در مرحله ۴ اینستالر، با خطای قطع اتصال یا تجاوز از حداکثر اندازه پکت مواجه می‌شوید. این خطا معمولاً روی جداولی نظیر `wp_options` (با رکوردهای ترنزینت سنگین یا کش المنتور) رخ می‌دهد.

### علت:
سرور MySQL مقصد تنظیمات پایینی برای متغیر `max_allowed_packet` دارد (مثلاً ۱ مگابایت یا ۴ مگابایت) و یک سطر دیتابیس حاوی کدهای سنگین از این سقف فراتر می‌رود.

### راه‌حل‌ها:
1. **مکانیزم خودکار بکاپینو:** استخراج‌کننده و ایمپورتور بکاپینو دستورات چندسطری حجیم `INSERT` را به صورت هوشمند به قطعات خردتر (Chunks) تقسیم کرده و پکت‌ها را در بازه‌های امن ارسال می‌کند تا هرگز از سقف تعیین‌شده فراتر نروند.
2. **افزایش مقدار در سرور MySQL:**
   * در فایل پیکربندی MySQL (`my.ini` در ویندوز/لوکال یا `/etc/mysql/my.cnf` در لینوکس) زیر بخش `[mysqld]` خط زیر را درج و سرور پایگاه داده را ری‌استارت کنید:
     ```ini
     max_allowed_packet = 64M
     ```
   * یا از طریق اجرای کوئری در phpMyAdmin با دسترسی root:
     ```sql
     SET GLOBAL max_allowed_packet = 67108864;
     ```

## 🛠️ ۲. خطای `Tablespace for table '...' exists. Please DISCARD the tablespace` (InnoDB Error 1813)

### نشانه:
حین ساخت جدول جدید در MariaDB یا MySQL در مرحله ۴ نصاب مستقل با خطای زیر مواجه می‌شوید:
```text
❌ [ERROR]: Tablespace for table '`db_name`.`wp_table`' exists. Please DISCARD the tablespace before IMPORT
```

### علت فنی:
موتور InnoDB و XtraDB برای هر جدول یک فایل فیزیکی مجزا با پسوند `.ibd` ذخیره می‌کنند. اگر در بازیابی‌های پیشین فرآیند ناگهان قطع شده باشد، یا کاربر در دیتابیس قبلی دیتابیس را پاک کرده اما فایل فیزیکی جدول روی دیسک قفل مانده باشد، سرور اجازه ساخت مجدد جدول با همان نام را نمی‌دهد زیرا فایل فیزیکی در مسیر سیستم فایل وجود دارد اما در دیکشنری دیتابیس ثبت نیست.

### راه‌حل‌ها:
1. **بازیابی خودکار و مقاوم بکاپینو:** موتور ایمپورت بکاپینو به محض تشخیص این خطا، به صورت خودکار دستور رفع انسداد زیر را ارسال می‌کند تا جدول پاکسازی و مجدداً ایجاد شود:
   ```sql
   DROP TABLE IF EXISTS `wp_table`;
   ALTER TABLE `wp_table` DISCARD TABLESPACE;
   ```
2. **راه‌حل در کنترل‌پنل / phpMyAdmin:**
   * اگر دیتابیس جدیدی برای نصب ساخته‌اید و چندین بار تست ناموفق انجام داده‌اید، کافی است در phpMyAdmin دیتابیس تستی را یک‌بار به طور کامل Drop کرده و یک دیتابیس تازه با همان نام بسازید تا فایل‌های قفل‌شده پاک شوند.
   * در صورتی که در سرور لوکال (XAMPP/Laragon) هستید، اطمینان حاصل کنید هیچ پروسه سرور MySQL دیگری در پس‌زمینه در حال کار نیست.

## 🛠️ ۳. خطای کلید خارجی `errno: 121 Duplicate key on write or update`

### نشانه:
حین ایجاد جدول دارای قیدهای کلید خارجی (Foreign Key Constraints)، خطای شماره ۱۲۱ برمی‌گردد.

### علت:
در MySQL، نام Constraintهای کلید خارجی در سطح کل سرور باید یکتا باشند. اگر دیتابیس قبلی یا جدول دیگری از همان نام قید استفاده کند، ساخت جدول با شکست مواجه می‌شود.

### راه‌حل‌ها:
* بکاپینو قبل از شروع ایمپورت، دستور `SET FOREIGN_KEY_CHECKS = 0;` را صادر می‌کند تا وابستگی‌ها موقتاً نادیده گرفته شوند.
* در صورت مواجهه با خطای ۱۲۱، اینستالر به صورت خودکار نام Constraint را بازنویسی کرده و کوئری را تکرار می‌کند.

## 🛠️ ۴. خطای تکراری `Duplicate entry '...' for key 'PRIMARY'`

### نشانه:
در هنگام ازسرگیری ایمپورت پس از یک قطعی، خطای تکرار کلید اصلی در جدول رخ می‌دهد.

### راه‌حل:
* سیستم ایمپورتور بکاپینو به صورت خودکار خطا را شناسایی کرده و دستور `INSERT INTO` را به صورت هوشمند به `INSERT IGNORE INTO` تبدیل می‌کند تا رکوردهای قبلی حفظ شده و رکوردهای باقیمانده بدون توقف ایمپورت شوند.
